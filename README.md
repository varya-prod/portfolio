# Varya Lavrova — портфолио продюсера

Статический сайт без сборки и зависимостей. Для просмотра откройте `index.html` в браузере. Для публикации можно загрузить папку целиком на статический хостинг.

## Концепция

- Кинематографичный первый экран с местом для видео и крупной типографикой.
- Шоурил как отдельная сцена сразу после первого экрана.
- 15 проектов в трёх разделах. Карточки открывают видео прямо на сайте.
- Плавное появление блоков, параллакс карточек, анимированная строка, кастомный курсор, переходы меню.
- Пороговая прокрутка между разделами для мыши и клавиатуры. На телефоне работают обычные свайпы с мягкой привязкой к началу раздела. В длинных разделах можно прокручивать содержимое внутри блока.
- Адаптивная версия и режим уменьшенного движения для пользователей, которые отключили анимации в системе.

## Как заменить содержимое

1. Для отдельного шоурила добавьте `assets/showreel.mp4` и укажите `const SHOWREEL_VIDEO = './assets/showreel.mp4';` в `app.js`. Пока шоурил остаётся заглушкой: ни один из роликов не обозначен как готовый монтаж шоурила.
2. Список проектов и переводы названий находятся в `projectGroups` в `app.js`. Видео воспроизводятся в окне проекта; кадры для карточек загружаются только по мере прокрутки. Для лучшей скорости можно позже добавить отдельные постеры WebP/AVIF.
3. При изменении контакта обновите адрес `varalavrova26@gmail.com` в `index.html`.

Кейс «Здесь будет свет» использует локальный файл из раздела Festival & VIP. В [архиве LIONS](https://www.lovethework.com/en/work/entries/highlighted-by-data-787224) работа указана как **Highlighted by Data**, Tele2 Kazakhstan, 2026, **Shortlisted Cannes Lions**. На [Jolbors](https://jolbors.com/en/awards/awards-international-2026/entry/1484/?list_type=longlist) кампания называется **There Will Be Light**. По данным владельца портфолио, Варя продюсировала постпродакшн и координировала семь специалистов.

В каталоге `assets/video` находятся 14 MP4 общим размером около 674 МБ; каждый файл меньше 100 МБ, самый большой — около 93,6 МБ. Карточки загружают видео-превью по мере прокрутки, а для видео в окне проекта задан `preload="metadata"`.

Если браузер не может открыть ролик, в окне проекта появится ссылка на скачивание исходника.

### Иллюстрации Вари

Иллюстрации подключаются в объекте `ILLUSTRATIONS` в `app.js`:

```js
const ILLUSTRATIONS = {
  hero: './assets/illustrations/hero.webp',
  about: './assets/illustrations/about.webp',
  contact: './assets/illustrations/contact.webp',
  projects: {
    '01': './assets/illustrations/project-01.webp'
  }
};
```

На первом экране и в контактах сейчас стоят сгенерированные временные иллюстрации `hero-placeholder.png` и `contact-placeholder.png`. Это оригинальные заглушки, созданные по общим визуальным признакам примеров Вари, а не её работы. В `ILLUSTRATIONS` уже прописаны пути к ним. После получения настоящих иллюстраций нужно заменить файлы и настроить масштаб, кадрирование и интенсивность движения под каждую композицию. Для отдельных персонажей удобны исходники с прозрачностью (PNG, WebP или SVG); для цельных сцен с фактурным фоном подойдут и обычные изображения.

## Архитектура

Для текущего одностраничного портфолио React не требуется: здесь нет сложного состояния приложения, личного кабинета или маршрутизации. HTML, CSS и JavaScript дают анимацию, фильтры, модальные карточки и видео с минимальным весом и без этапа сборки. Если появятся десятки кейсов с отдельными страницами и редактором контента, стоит перейти на статический генератор (например, Astro), сохранив такую же структуру данных.

Порог перехода между разделами на компьютере задаёт `scrollThreshold` в `app.js` (сейчас 115 px). На телефонах браузер обрабатывает свайпы нативно, без перехвата JavaScript. При системной настройке уменьшенного движения используется обычная прокрутка. Системный курсор скрывается только там, где работает кастомный курсор.

## Ограничение доступа

На GitHub Pages добавлена только форма-перехватчик для интерфейса. Это не настоящая защита: HTML, JavaScript, видео и картинки остаются доступны напрямую, а хеш пароля можно подобрать офлайн. Не используйте этот способ для конфиденциальных материалов или паролей, которые используются где-либо ещё.

Чтобы включить форму, задайте SHA-256-хеш в `ACCESS_PASSWORD_HASH` в `app.js`, заменив `REPLACE_WITH_SHA256_HASH`. Хеш можно получить локально в консоли браузера на HTTPS-странице:

```js
const password = prompt('Введите новый пароль локально');
if (!password) {
  console.log('Пароль не задан — введите непустой пароль и запустите код снова.');
} else {
  const digest = await crypto.subtle.digest('SHA-256', new TextEncoder().encode(password));
  console.log(Array.from(new Uint8Array(digest), (byte) => byte.toString(16).padStart(2, '0')).join(''));
}
```

Не отправляйте пароль в чат и не сохраняйте его в репозитории. GitHub Pages подходит для публичной версии; обычная приватность репозитория не закрывает опубликованный сайт. Приватная публикация Pages доступна только в рамках GitHub Enterprise Cloud для определенных организационных репозиториев.

Для закрытого портфолио рекомендуемый путь — статический хостинг с проверкой доступа до выдачи файлов, например Cloudflare Access на домене и на адресах предпросмотра. После выбора хостинга нужно отдельно настроить политику доступа и проверить, что прямые ссылки на видео и изображения тоже закрыты. Пароли и ключи не следует хранить в репозитории.

## Проверки

`node --check app.js` — проверка синтаксиса JavaScript. Ручную визуальную проверку в браузере нужно провести после появления доступного браузера или локального сервера.

(async () => {
  const password = prompt('');
  if (password === null) return;
  const digest = await crypto.subtle.digest(
    'SHA-256',
    new TextEncoder().encode(password)
  );
  console.log(Array.from(new Uint8Array(digest), b =>
    b.toString(16).padStart(2, '0')
  ).join(''));
})();
